# Reconstruction and forecasting — one rig, one decoder, two masks

**Nothing has been measured yet.** This page was written on 2026-09-18, before the first
run, so that what follows is a prediction and not a reading. Phases 3 and 4 of
`EVALUATION_PLAN.md`.

The rig is the same in both halves. A pretrained backbone is frozen and in `eval()`,
excluded from the optimizer; a `tinydec` decoder — `dec_depth 1`, `dec_dim 64`, about 0.4×
the encoder's FLOPs — is trained from scratch on top of it; the score is the **mean
per-DOF angular error in degrees**, taken through `atan2(sin, cos)` on the held-out
tokens. The two halves differ in which tokens are held out and in nothing else.

## Pre-registration: reconstruction does not rank cells

Written down here before the table exists, so it cannot be discovered afterwards.

Better representations often reconstruct *worse*. A near-identity encoder passes
everything through and decodes beautifully while abstracting nothing, which is precisely
the encoder a masked-reconstruction objective is happiest to produce and precisely the one
a downstream probe has least use for. This matrix already hints at it: `loss_p` cells
reconstruct the easiest target and probe worst on BABEL-60 (0.3446 against 0.3734).

**The predicted outcome is an inversion**: the degrees column ranks the nine cells roughly
inversely to their BABEL-60 macro mAP. If that is what the table shows, it is the expected
result and it is evidence about the metric, not about the cells. If instead reconstruction
tracks mAP, that is the surprise and is worth a paragraph of its own.

So phase 3 is a **diagnostic**. It answers "how much of the raw signal survives in the
tokens", which is a fact worth having beside the probe numbers and is not a ranking. No
cell is declared better because it reconstructs better. Forecasting (the `suffix` mask) is
a different question and is read as a ranking, against its floors.

## What is fixed, and why

**The decoder is tiny and identical in every cell**, and shared by both masks. This is the
confound that has already bitten this project once: `results/decoder_capacity/README.md`
documents that `medium`'s pretraining decoder runs at 8.6× the encoder's FLOPs and can
compute torque from kinematics by itself — a plain linear map recovers R² = 0.685 — which
is the standing explanation for why the `pkd` loss channel looks inert. A probe decoder
that size would rank decoders rather than backbones.

**The target is `sin, cos` only.** Cells differ on the *input* axis (`p`/`pk`/`pkd`), so
the pose channels are the only ones every cell has; a wider target would score the nine
cells on nine different problems. Each cell's own pretraining loss is explicitly not this
metric — `loss_p` scores 2 channels and `loss_pkd` scores 5, per-token standardized, so
those numbers were never on one scale.

**Phase 3's mask is `mask_ratio = 0.75`, uniform** (`tau <= 0`), identical for every cell.
Off pretraining's 0.90 on purpose, so the number is not each cell's own training objective
wearing a new name. Uniform because motion-aware masking draws its holes through a
per-cell config and would hand different cells windows of different difficulty.

**Phase 4's mask is the last 8 time patches across all 43 DOFs**, as a fixed index set
rather than a draw. 8 × 8 frames = 64 frames = 1.067 s at 60 Hz, reported as "~1 s" — 1 s
exactly is 7.5 patches and does not exist. Taken out of the existing 240-frame window
rather than by building a longer one, which would mean a new `min_frames`, a smaller
eligible sample pool and a new collate to buy a horizon the current window already
contains.

**Phase 4 publishes its floors in the same table**, same unit, same split: zero-velocity
(hold the last observed frame) and constant-velocity extrapolation, both computed inside
the same validation loop with no model at all. Non-negotiable: at 60 Hz much of a 1 s
horizon is predictable from the last two frames, so without them the table cannot
distinguish a good backbone from an easy horizon. A gap to the floor that sits inside the
seed spread is reported as such, not omitted.

## Running it

```
./scripts/reconstruction_matrix.sh                       # both masks, canonical run
SEEDS="1 2 3" ./scripts/reconstruction_matrix.sh         # the three-seed matrix
MASKS=suffix DRY=1 ./scripts/reconstruction_matrix.sh    # print the plan and exit
uv run python results/reconstruction/gen.py              # rebuild the tables below
uv run python scripts/probe_reconstruction.py --self-check
```
